&emsp; A interface do usuário representa a camada visual do sistema desenvolvido, por meio da qual será possível executar tarefas e acompanhar operações. Além do desenvolvimento de um wireframe para a [interface utilizada pelo coordenador da operação](../sprint-1/proposta-de-interface.md), também foi elaborado um wireframe para a interface destinada ao administrador das operações. Esse perfil será responsável pela atribuição das operações, bem como pela adição de novos drones e funcionários ao sistema.

&emsp; Os wireframes foram desenvolvidos com o objetivo de servirem como base para a construção do protótipo de alta fidelidade, que posteriormente será utilizado na validação da interface com os usuários.

&emsp; O fluxo do administrador tem início na tela de login, que será a mesma utilizada pelo coordenador, apresentada na seção de [Interface](../sprint-1/proposta-de-interface.md). Após acessar a plataforma, sua principal atividade será realizar a atribuição das operações, ou seja, associar um funcionário ao drone responsável por determinada operação. Por esse motivo, a primeira tela de administração foi projetada para permitir essa ação de forma direta.

&emsp; Para realizar a atribuição, o administrador deverá selecionar um drone entre as opções disponíveis e, em seguida, escolher um operador entre os profissionais disponíveis. Todas as atribuições realizadas serão exibidas em uma tabela localizada abaixo, contendo as informações mais relevantes de cada associação, além de opções para edição ou exclusão dessas atribuições.

&emsp; Os wireframes desenvolvidos representam uma primeira visão da interface do sistema, tanto para o administrador da plataforma quanto para o operador do drone. Eles servirão como base para o desenvolvimento do protótipo de alta fidelidade, que será posteriormente utilizado na validação da interface com os usuários.

## Protótipo de Alta Fidelidade

&emsp; A partir dos wireframes desenvolvidos anteriormente, foi elaborado o protótipo de alta fidelidade da plataforma, com o objetivo de representar de forma mais próxima a experiência final do usuário. O protótipo permite validar aspectos visuais, fluxo de navegação e organização das informações antes do desenvolvimento completo da aplicação.

## Operador

&emsp; O fluxo do operador inicia-se na tela de login, utilizada para autenticação e acesso à plataforma. Após o login, o operador é direcionado para a tela de seleção do drone disponível para operação. Também foi desenvolvido um histórico de operações, permitindo a visualização das atividades realizadas anteriormente.

## Conclusão
&emsp; O protótipo de alta fidelidade possibilitou uma representação muito mais detalhada e próxima do resultado final esperado para a plataforma, permitindo visualizar com maior clareza a estrutura das telas, a disposição das informações e o comportamento das principais funcionalidades do sistema. A partir dele, foi possível validar não apenas a organização dos fluxos de navegação, mas também identificar melhorias relacionadas à usabilidade, consistência visual e experiência do usuário durante a interação com a solução.

&emsp; Além disso, o desenvolvimento do protótipo permitiu simular cenários reais de uso da plataforma, facilitando a análise de como os usuários irão interagir com os recursos disponíveis no sistema. Esse processo também auxiliou na identificação de inconsistências presentes nas versões iniciais dos wireframes, possibilitando ajustes antes da etapa de implementação, reduzindo retrabalho e garantindo uma solução mais alinhada às necessidades do projeto e das personas definidas.
